# 金融 Agent 低 Token 编排规范

## 1. 目标

用最少必要的 Skills 和数据完成任务，但不得降低数据可信度、投资风险揭示、用户数据隔离和用户明确要求。

## 2. 复杂度

- S0：概念解释，0 个领域 Skills。
- S1：单项研究，1 个主 Skill。
- S2：多维分析，1 个主 Skill + 按需辅助，通常不超过 3 个。
- S3：选股到交易、组合风险或绩效闭环，分阶段执行。

## 3. 渐进加载

- L0：任务意图、市场、标的和已知上下文；
- L1：主 Skill；
- L2：明确依赖的辅助 Skill；
- L3：指标口径、数据源规范、策略参数、风险策略和模板。

不要默认加载全部 Skills、数据源文档或所有市场行情。

## 4. 数据查询复用

同一标的、同一数据源、同一字段和同一时间范围的数据可复用；但行情时间变化、查询范围变化、口径变化或数据质量问题需要重新查询。缓存数据必须保留原始时间戳，不能伪装为最新数据。

## 5. 阶段交接

只传递 market、instrument、period、source、timestamp、currency、adjustment、facts、assumptions、decisions、risks、pending 和 next。

## 6. 不可压缩的质量底线

不能因节省 Token 而省略数据来源和时点、市场标识、风险限制、用户授权、关键计算口径、回测防前视、样本量和不确定性。
