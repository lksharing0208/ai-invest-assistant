# 投资策略分析与验证

## 1. 职责

将策略想法转化为有版本、有参数、有状态、有验证边界的规则规格。该 Skill 不代表策略已经有实盘收益，也不自动下单。

## 2. 策略规格

每个策略必须定义：
- 策略 ID、名称、版本、适用市场和标的范围；
- 信号周期和数据频率；
- 入场、加仓、减仓、退出和失效条件；
- 指标公式、阈值、参数和缺失数据处理；
- 状态定义、状态转移和重复信号处理；
- 仓位及风险约束；
- 交易成本、滑点和可成交假设；
- 回测区间、基准和评估指标。

参数放在独立策略配置，不将未验证阈值写入通用 Skill。

## 3. 突破—回踩—启动策略框架

当用户选择该策略时，可按以下逻辑组织：
1. 股票池预过滤：市场、流动性、证券状态及基础排除条件。
2. 突破有效性：突破参考区间、收盘确认、成交特征和市场环境。
3. 回踩状态机：未突破、突破确认、等待回踩、回踩有效、回踩失败、等待再启动、再启动确认、策略失效。
4. 再启动判断：价格重新满足触发条件，并检查量价与市场环境。
5. 多维评分与分级：按用户提供或配置的评分项和权重计算。
6. 行业/板块/概念强度：检查个股信号是否获得行业环境支持。
7. 交易计划：由 trading-plan 与 risk-management 形成入场、止损、目标和仓位边界。

具体状态转移、有效期、容忍区间及评分阈值必须由策略配置定义。不能把示意状态机当作已验证的交易系统。

## 4. 回测验证

- 使用时点可得数据，避免未来数据泄漏；
- 处理复权、分红、停牌、退市和历史成分变更；
- 模拟交易成本、滑点、涨跌停、最小交易单位和不可成交；
- 区分样本内、样本外和滚动验证；
- 与合理基准比较，检查收益、波动、最大回撤、换手、盈亏比和稳定性；
- 执行参数敏感性与子区间分析；
- 报告幸存者偏差、数据缺失、过拟合和市场制度变化风险。

## 5. 输出

策略版本、适用范围、规则、状态机、参数表、数据要求、回测设计/结果、基准比较、稳健性、风险、失效条件和未验证事项。
