# 交易日志与复盘

## 1. 数据隔离

交易日志属于个人金融数据。所有读取和写入必须绑定经过授权的用户、租户和账户上下文；不得仅凭请求参数中的 userId 信任调用者身份。

## 2. 记录模型

根据实际系统字段记录：
- 用户与账户标识；
- 市场、证券及交易方向；
- 计划时间、委托时间、成交时间；
- 委托/成交价格、数量和币种；
- 手续费、税费和其他成本；
- 计划/策略版本和触发条件；
- 买卖理由、风险判断和退出原因；
- 成交状态、撤单/失败原因；
- 对应持仓批次和复盘结果。

字段是否存在以真实 API/数据库设计为准，不将此示例直接当成已部署 Schema。

## 3. 操作流程

1. 校验用户身份、账户权限和记录归属。
2. 区分计划、委托、成交和持仓变化，不把计划记录当成已成交。
3. 校验数量、价格、方向、时间和费用口径。
4. 对重复提交使用业务幂等标识或由系统定义的去重规则。
5. 对成交更正、撤单和冲正保留审计轨迹，不覆盖历史事实。
6. 记录计划与实际成交差异。
7. 按用户需要生成单笔、日度、周度或策略复盘。

## 4. 复盘维度

- 是否遵循计划；
- 信号和数据是否有效；
- 入场/退出偏差；
- 费用、滑点和流动性影响；
- 盈亏与风险预算差异；
- 可重复的流程改进项。

不以单笔盈亏简单评价交易决策质量。

## 5. 输出

记录摘要、账户范围、记录状态、关键字段完整性、计划执行差异、复盘结论和待补信息。
